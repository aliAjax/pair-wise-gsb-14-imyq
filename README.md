# 油品价格维护

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Naive UI
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 并发/恢复链路模拟：`npm run sim`（72 项断言）

数据保存在浏览器 localStorage 中，围绕换班时两个窗口同时调价的并发问题，把
**调价记录（只追加审计流水）、有效价快照（版本化完整快照）、待处理修订**
三者串联起来。

## 数据模型（`src/price/`）

- `types.ts`：`PriceDoc` 文档（`version` / `effective` / `snapshots` /
  `pending` / `audit` / `retries`）。
- `store.ts`：纯 TS 领域逻辑（`PriceStore`），含迁移、差异分析、快照恢复。
- `usePrice.ts`：Pinia 适配层，把文档变化接入 Vue 响应式。
- `sim.ts`：双窗口端到端模拟（mock localStorage / storage 事件 /
  BroadcastChannel），不依赖浏览器。

## 并发调价规则

1. **提交带基线版本**：打开页面时锁定 `baselineVersion`，本窗口每次提交都带它；
   即使通过 storage 事件看到了同伴的新版本，基线也不推进（只有本窗口自己
   确认/恢复后才推进）。
2. **另一窗口改了字段 → 需重新确认**：经理确认生成新版本后，系统对比基线快照，
   未完成修订若改过的字段同伴没动，判为 `needs_recheck`，值班经理核对后
   点"重新确认"把基线推进到当前版本，再确认生效。
3. **同一字段两边都改 → 并排冲突**：本窗口值与同伴已生效值并排列出，
   逐项选择"本窗口 / 同伴 / 自定义"，裁决后才生成新快照。
4. **确认后才更新统计**：平均挂牌价等指标只取当前 `effective` 快照，
   待处理修订不进统计；每次确认生成一份版本号递增的完整快照。
5. **旧数据迁移**：首次打开时把旧版平铺的 `RecordItem[]` 迁移为
   v1 完整有效价快照（生效中记录入价、待确认记录转为基线 v1 的待处理修订），
   并补齐 `schemaVersion` / `version`；迁移本身留审计。
6. **写入失败恢复**：写入 localStorage 失败时，内存立即回退到最后一个
   完整快照，未完成修订全部保留并按恢复点重判；失败动作（提交/确认/回退，
   含裁决结果）进入重试队列，可反复重试或放弃。页面上的"模拟下一次写入失败"
   按钮可演练整条链路。
7. **跨窗口同步**：通过 BroadcastChannel + storage 事件双通道接收另一窗口的
   完整文档，本地未完成的重试项合并保留。
